# HTML → видео: несколько вариантов, выбор лучшего, финальная сборка

Claude сильнее всего в дизайне на HTML/CSS. Поэтому видео делаем так: пишем анимацию в HTML,
рендерим её в видео, **смотрим на результат глазами** (кадры), сравниваем варианты и улучшаем.

## Требования
- `node` + `playwright` (с Chromium), `ffmpeg`. Проверка: `bash scripts/check-env.sh`.

## Быстрый старт
```bash
cp references/template-scenes.html work/<название>/v1.html     # шаблон на движке сцен
node scripts/render.mjs work/<название>/v1.html --preset vertical-preview --duration 20 --out work/<название>/v1.mp4
```
- `references/engine.js` — движок сцен: фон, субтитры с подсветкой (`*слово*`), прогресс, переходы, easing (`E.pop`, `E.type`, `E.set`).
- `references/parts.js` — детали: маскот `P.bot`, иконки `P.icon`, окно macOS `P.win`, пузыри чата.
- `references/design-notes.md` — что делает ролик «живым» (сюжет, хук, ритм, субтитры). **Прочитай перед написанием вариантов.**
- Примеры готовых роликов: `examples/` (`duolingo-5min` — 9:16, 31 с, 60 fps, без людей: весь ролик — один 5-минутный урок с таймером, 3D только в сундуке-награде, финал собран из трёх вариантов по рубрике; `mango-ad` — 9:16, 27 с, 3D-фуд-реклама «сочное манго»: свет, шейдеры мякоти, капли, слоу-мо всплеск; `3d-demo` — 9:16, 30 с, 3D-движок: продукт-шот, логотипы, маскот, телефон, материалы; `claude-ad` — 16:9; `chatgpt-ad` — 9:16, 25 с; `duolingo-ad` — 9:16, 40 с, 60 fps с сюжетом и демонстрациями; `claude-self-ad` — 9:16, 39 с, 60 fps, реклама самого Claude с мета-поворотом).
- Размер файла: ролик 40 с / 60 fps ≈ 10 МБ; если нужен лимит меньше — `--fps 30` или перекодируй `ffmpeg -i in.mp4 -crf 24 out.mp4`.

## Главные принципы качества
1. **Показывай, а не рассказывай.** Любое утверждение в ролике — это сцена-доказательство, а не надпись.

   | Утверждение | Что показать |
   |---|---|
   | «Пишет код» | печатается запрос, затем по строкам появляется код |
   | «Объясняет понятно» | реальная ошибка (`she drink`), подсветка и правило «+s», сова с пояснением |
   | «Учит на практике» | палец тапает по словам, фраза собирается, зелёная панель «Правильно!» |
   | «Серия 346 дней» | счётчик 1→346 с огоньком, календарь заполняется волной, уведомление, поздравление с конфетти |
   | «Игра» | таблица лиги, где строка героя поднимается на 1-е место, и +XP |

2. **Описывай происходящее.** В каждой сцене два слоя текста: маленький заголовок-ярлык сверху (`<div class="kick">`: «Урок», «Лига») и субтитр внизу с подсвеченным ключевым словом (`cap: 'Разбирает *ошибки* понятно'`). Полные фразы лучше однословных лозунгов.
3. **Плавность.** Финал рендерится с `--max` (**60 fps + motion blur**). Всё живёт непрерывно: пружинные появления (`E.spring`, `E.pop`), медленный наезд камеры (`cam: [1, 1.05]`), покачивание маскота, моргание (`P.blink`), касания пальцем с рябью (`P.touch`), счётчики (`E.count`), переходы `circle`/`wipe`/`left`. Не оставляй статичных кадров дольше ~0.5 с.
4. **Сюжет:** хук (боль/юмор) → демонстрации → «лучшие качества» → кульминация (награда/результат) → призыв. 30–45 с для рекламы.
5. **Три варианта — три разные идеи**, а не три раскраски (например: «счётчик серии», «урок вживую», «диалог с маскотом»). Затем финал собирается из лучших сцен всех вариантов.

## Звук и максимальное качество рендера
**Звук собирается сам из сцен.** В сцене: `sfx: [[0.5, 'pop'], [1.2, 'pour', {dur: 2, gain: .7, pan: -.3}]]` (время — от начала сцены). В `E.run`: `music: {style: 'lofi', from: 'scene:2+0.6', drums: 'scene:4+1.6', bpm: 86, gain: .5}` — тёплый лоу-фай, бит вступает в момент кульминации. `render.mjs` синтезирует дорожку (`scripts/sfx.py`, нужен `python3` + `numpy`), приглушает музыку под эффектами и нормализует громкость до −14 LUFS (стандарт соцсетей).
- Звуки: `alarm click tick snooze whoosh whoosh_down rise thud pop psst pour clink slurp chime success sparkle swell bass drip splash slice squish` (`python3 scripts/sfx.py --list`, послушать всё: `--demo demo.wav`).
- Правило: **каждое видимое действие — свой звук** (тап → `click`, банка упала → `thud`, налили → `pour` + `clink`, награда → `success` + `sparkle`, переход → `whoosh`). Тишина между действиями — тоже приём.
- Своя музыка: `--audio track.mp3` (смешивается со звуками сцен); без звука: `--no-sfx`.
- Проверить звук глазами (если нет возможности слушать): `ffmpeg -i out.mp4 -lavfi showspectrumpic=s=1600x500 spec.png`.

**Пресет максимального качества:** `node scripts/render.mjs final.html --preset vertical --max` = 60 fps + **motion blur** (3 подкадра на кадр, затвор 180°) + x264 `slow`/`animation`, crf 15. Подкадры: `--motion-blur 4`, затвор: `--shutter 0.5`. Стоит в N раз дороже по времени — для превью не нужен.
- Длина ролика берётся из сцен сама (`--duration` можно не указывать).

## 3D: объекты, свет, камера (`references/engine3d.js`)
Настоящий 3D внутри сцен: студийный свет, мягкие тени, отражения, материалы, объёмный текст и логотипы. Основа — Three.js (MIT), ставится сама в `vendor/` при первом 3D-рендере (`node scripts/setup-3d.mjs`).
Шаблон: `references/template-3d.html` (importmap + `<script type="module">`). Пример всего сразу: `examples/3d-demo/reel.html`.

```js
let v, can;
{ dur: 5, bg: '#f3e4d0',
  mount(el) { v = E3D.view(el, { floor: '#f3e4d0' }); can = v.add(E3D.can({ label: { title: 'ЗАРНИЦА', sub: 'COLD BREW' } })); },
  update(t) { can.rotation.y = t * .8; v.orbit({ target: [0, .8, 0], radius: 6, angle: -20 + t * 8, height: 1 }); v.render(t); } }
```
- **Сцена:** `E3D.view(el, {floor:'#цвет'})` — бесшовная студия с тенями; без `floor` фон прозрачный (виден 2D-фон сцены, тень ложится на него). Камера: `v.orbit({target, radius, angle, height})`, `v.fit(объекты)` — сама подберёт дистанцию под вертикальный кадр.
- **Материалы** `E3D.mat(kind, color)`: `clay` (пластилин), `plastic`, `glossy`, `paint`, `metal`, `chrome`, `gold`, `glass` (преломление — ставь за стеклом что-то цветное), `emissive`, `matte`.
- **Объекты:** `box sphere capsule cylinder torus cone`, `can` (банка с этикеткой), `bottle`, `phone({screen(ctx,W,H,t)})` (живой экран), `mascot()` (персонаж: `userData.setMood/blink/petals`), `confetti(n,{at})`, `glb('model.glb')` (свои модели, анимации идут по t).
- **Текст и логотипы:** `text3D('ЗАРНИЦА', {size, kind, color})` — выдавленные буквы, кириллица работает; `logo3D('Telegram')` / `logoTile3D('Telegram')` — логотип найдётся сам (scripts/logos.mjs) и выдавится в цвете бренда; `label('текст')` — плоская надпись в пространстве.
- **Анимация** — только из `t`: падение `y = h*(1-f²)`, удар — сплющивание `scale(1+.08s, 1-.12s)`, пружины `E.spring`. Объект с `userData.tick(t)` обновляется сам.
- **Скорость:** 3D считается на процессоре (программный WebGL): ~0.6–1 с на кадр 1080×1920, стекло ~2 с. Рендер для 3D идёт в 1 поток (так быстрее), превью — `--preset vertical-preview --draft3d`. Motion blur для 3D умножает время на N — обычно хватает 60 fps без него.

### Свет и шейдеры (как в предметной/фуд-съёмке)
- **Пресеты света** `E3D.view(el, {light})`: `studio` (мягкий универсальный), `product` (софтбоксы + два контровых — глянец, еда), `sunset` (тёплый низкий + холодное заполнение), `dramatic` (жёсткий верх, сильный контур, тёмное окружение — слоу-мо, жидкости). Отражения берутся из HDR-«студии» из светящихся панелей: `envBase`/`envTop` — цвет низа/верха окружения, `beauty` — сила фронтального софтбокса (блики на мокром, смотрящем в кадр), `backdrop` + `backdropColor` — панель позади (отражается в лужах/полу при низкой камере; держи 1–2, иначе всё белеет).
- **Пост-обработка:** `bloom: {strength, radius, threshold}`, глубина резкости `dof: {focus, aperture, maxblur}` + `v.focus([x,y,z])` каждый кадр, цветокор `grade: {contrast, saturation, warmth, vignette, grain, lift}`.
- **Подвижный софтбокс:** `const sb = v.softbox({w, h, intensity, color, pos, target})`, затем `sb.userData.move([x,y,z])` по t — длинный блик «ползёт» по мокрой поверхности (главный приём «сочности»).
- **Свои шейдеры без потери света/теней:** `E3D.enhance(material, {color, height, bump, coat, coatBump, rough, sss, rim, pre, post, uniforms, seed})` — GLSL-кусочки внедряются в обычный `MeshPhysicalMaterial`. Доступны `snoise/fbm/fbm3/srgb`, `P` (позиция), `uTime`. `height` — процедурный рельеф; `coat` — свои волны лакового слоя (плёнка сока → дробные влажные блики); `sss` — просвет на контровом свете; `post` — правка итогового цвета (например, растворить край в фоне). Тяжёлый шум считай один раз в `pre` и переиспользуй — это главный способ ускорить рендер.
- **Жидкость:** `E3D.liquidMat(color, {tint, depth, transmission, glow})` — преломление + поглощение по толщине + свечение на просвет (сок не темнеет на тёмном фоне).
- **Типичные ошибки (проверено):** слишком сильный `sss` или свет на насыщенном оранжевом → красный канал клиппится и тонмаппинг делает цвет **розовым** (проверяй пипеткой: у мякоти манго синий канал ≈ 30, не 70+); светлое окружение + шероховатый спекуляр → белёсый «налёт» на гранях (снижай `specularIntensity`, блики оставляй лаку); край плоскости-лужи даёт жёсткий «горизонт» — растворяй в цвет фона через `post`.

### Еда и жидкости (`references/food3d.js`)
```js
import { F } from '../../references/food3d.js';
const m = F.mango();                                   // целое манго: кожура с румянцем и чечевичками, лист, черенок
const c = F.mangoCut();  v.add(c.body, c.cheek);       // разрезанное: «щёчка» + тело с волокнистой косточкой; двигай/поворачивай части
const hh = F.hedgehog(); hh.userData.setK(k);          // «ёжик»: 0 — плоский надрезанный срез, 1 — кубики вывернуты
v.add(F.drops([...F.spray({origin, dir, at, slow}), F.drip({pos, t0, t1, slow})])); // все капли — один InstancedMesh
v.add(F.splash({at, slow}), F.pool({r, bg, impacts: [[x, z, t, сила]], slow}));   // корона + столбик + рябь на лужице
```
- Капли на поверхности: `F.mangoSurface(lon, lat)` → точка и нормаль на кожуре; `F.bead({pos, to, t0, t1, t2})` — капля сползает.
- `slow` — коэффициент слоу-мо (0.4 = в 2.5 раза медленнее); время удара для звука считай из той же формулы, что и падение, а не подбирай на глаз.
- «Сочность» показывай действиями: капли выступают на срезе, сползают и срываются; брызги — из линии разреза наружу (не из центра плода); слоу-мо падения капли с короной; блик ползёт по мокрой мякоти. Звук: `slice` + `squish` на разрезе, `drip` на каждой капле, `splash` на ударе.
- Скорость: шейдерная мякоть + стекло-сок ≈ 2.5–6 с на кадр 1080×1920 → финал такой сцены рендери в `--fps 30` (≈1 ч на 27 с), превью — отдельными кадрами через `frame.mjs`.

## Логотипы брендов (ищутся и подставляются сами)
В HTML пишешь `P.logo('Duolingo', 12)` или `P.logoTile('Telegram', 24)` — при рендере `scripts/render.mjs` сам находит логотипы, кладёт их в `assets/logos/` и подключает `logos.js` рядом с HTML (отключить: `--no-logos`).

```bash
node scripts/logos.mjs get "Duolingo"            # найти один логотип и показать источник/лицензию
node scripts/logos.mjs get duolingo.com          # по домену/URL — искать на сайте бренда
node scripts/logos.mjs search tele               # что есть в базе simple-icons
node scripts/logos.mjs auto work/ad/final.html   # найти все P.logo(...) из HTML (render делает это сам)
```
Порядок поиска: **свой бренд-кит** `assets/logos/_custom/` → кэш → **simple-icons** (npm, 3000+ брендов, официальный цвет, перекрашивается `{color}`) → **сайт бренда** (`<link rel=icon>`, `<img class=logo>`, JSON-LD, inline-svg) → **Wikimedia Commons** (с лицензией) → favicon (низкое качество).
- `P.logoTile(name, size, {bg,color})` — плитка: цвет бренда + белый знак; `P.logo(name, size, {color:'brand'|'#fff'|…})` — просто знак.
- Не нашёл логотип — рисуется текстовая плашка с названием, ролик всё равно рендерится; сообщи пользователю, что не нашёл, и предложи положить файл в `assets/logos/_custom/<название>.svg`.
- Нужен точный фирменный файл (OpenAI, Microsoft, Amazon и др. убраны из simple-icons по просьбе владельцев) — используй `_custom` или домен: `logos.mjs get openai.com`.
- В сети нет доступа к сайтам (облачная среда с ограничением)? Работают simple-icons (через npm) и `_custom`; остальное требует открытых хостов — скажи об этом пользователю, не подделывай логотипы.
- **Права.** Логотипы — товарные знаки владельцев. Используй для упоминания/демонстрации бренда по просьбе пользователя; не имитируй официальную рекламу и не создавай впечатления одобрения владельцем; в отчёте назови источник каждого логотипа (поле `source`/`license` в `assets/logos/<бренд>.json`). Проверка инструмента: `node scripts/logos.selftest.mjs`.

## Процесс

### 1. Бриф
Уточни (или выбери разумные значения по умолчанию): тема/текст, аудитория, длительность (реклама 20–30 с, история до 60 с),
формат (по умолчанию вертикальный 1080×1920 для Reels/Shorts/TikTok; 1920×1080 и 1080×1080 — по запросу), fps (30), стиль, цвета/шрифты.
Составь короткую раскадровку: хук → проблема → решение → демо → призыв. Для рекламы бренда рисуй своего маскота, а настоящий логотип подставляй через `P.logo('Бренд')` (см. раздел «Логотипы»).

### 2. Три и более РАЗНЫХ варианта
Создай рабочую папку `work/<название>/` и в ней `v1.html`, `v2.html`, `v3.html` (можно больше).
Варианты должны отличаться концепцией, а не мелочами. Например: (а) история с маскотом, (б) продуктовое демо с карточками,
(в) быстрые склейки с крупной типографикой. Разная композиция, палитра, ритм.
Каждый файл — самодостаточный HTML (без внешних загрузок, шрифты — системные или встроенные).
Правила анимации — в `references/animation-contract.md`; стартовый шаблон — `references/template.html`.

### 3. Рендер каждого варианта
Варианты — в превью-разрешении (быстро), финал — в полном:
```bash
node scripts/render.mjs work/<название>/v1.html --out work/<название>/v1.mp4 --preset vertical-preview --duration 21
node scripts/render.mjs work/<название>/final.html --out work/<название>/final.mp4 --preset vertical --max
```
Рендер детерминированный и параллельный (по числу ядер): время ставится вручную на каждый кадр, рывков и пропусков нет.
`--from 5 --to 9` рендерит только фрагмент. Один кадр без видео: `node scripts/frame.mjs v1.html 3.5,7 work/<название>/frames --width 540 --height 960`.

### 4. Анализ — обязательно смотреть
```bash
bash scripts/contact-sheet.sh work/<название>/v1.mp4 work/<название>/v1-sheet.png 12
```
Открой `*-sheet.png` и отдельные кадры через Read (изображения читаются визуально). Оцени по
`references/rubric.md` (сумма из 8 критериев по 5 баллов): читаемость, иерархия, ритм, плавность, баланс, цельность, соответствие брифу.
Для каждого варианта запиши: баллы по критериям, что получилось **лучше всего**, что **слабее всего**.
Не оценивай по коду — только по тому, что видно на кадрах. Если что-то неясно — сделай кадры плотнее
или в нужные моменты: `bash scripts/contact-sheet.sh <mp4> <png> 12 <start_s> <end_s>`.

### 5. Выбор лидера и синтез
- Выбери лучший вариант по суммарной оценке.
- Составь список «заимствований»: конкретные удачные решения из остальных вариантов
  (например, «типографика из v2», «анимация появления из v3», «палитра из v1»).
- Создай `final.html` на базе лидера и внеси эти правки. Исправь слабые места лидера.

### 6. Итерация и проверка финала
Отрендери `final.mp4`, снова сделай contact sheet, сравни с лидером. Если финал не лучше
лидера по рубрике — исправь и повтори (максимум 3 итерации). Затем покажи пользователю
результат: путь к `final.mp4`, краткую таблицу оценок вариантов и список того, что заимствовано откуда.

### 7. Звук (по желанию)
`ffmpeg -i final.mp4 -i music.mp3 -shortest -c:v copy -c:a aac final-audio.mp4`

- Фирменных **маскотов** брендов не копируй — рисуй своего персонажа. Логотипы брендов — только через `scripts/logos.mjs` (с указанием источника и прав).
- Не пропускай шаг 4: решение принимается по увиденным кадрам, не по предположениям.
- Все артефакты складывай в `work/` (в `.gitignore`), в репозиторий коммить только навык и примеры.
- Если Chromium/ffmpeg недоступны — скажи об этом прямо, не имитируй результат.
